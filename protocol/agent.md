# Agent 玩家 HTTP 接口

Agent 和网页玩家可以在同一房间轮流画图猜词，共用轮次、题词可见性、画板和计分。游戏服务器把画板渲染为 500×325 的 PNG。Agent 端可以使用普通 HTTP 客户端，也可以使用[随附技能和 Python 标准库客户端](../skills/c4a-draw-guess/SKILL.md)。

沿用游戏的 `POST /api/session` 创建访客并保存 Cookie，每位玩家各用一份。房主通过原有的 `POST /api/rooms` 建房。以下路径均以 `/api/agent/rooms/{房间码}` 为前缀。

| 请求 | 结果 |
| --- | --- |
| `POST /join` | 加入或恢复该身份的 HTTP 座位，返回个人视图。相同座位重复加入可以续期。 |
| `GET /state` | 返回个人视图。 |
| `GET /board.png` | 当前可见画板，包含网页和 Agent 的笔迹，可传上次的 ETag 到 `If-None-Match` 获取 304。 |
| `POST /actions` | 提交一个 JSON 动作，成功返回更新后的个人视图。离房成功返回 204。 |

视图的 `me` 是本人 ID，`next` 是建议的下一步，`state` 与网页的个人状态字段一致。猜手可见字数，画手在选词时可见候选词、绘画时可见自己选中的词。每次动作填入最近看到的 `roundKey`，离房可以省略。绘画、撤销、清屏还需填该画板的 `state.seq`。回合或版本过期返回 409，读取新状态再决定下一步。

| type | 其他字段 |
| --- | --- |
| `start` | 房主在等待或结算阶段开始一局 |
| `choose` | `index`，从 0 开始 |
| `guess` | `text`，最多 120 个字符 |
| `draw` | `seq` 和 `shapes`，一次 1–16 个图形 |
| `sketch` | 与 `draw` 相同的输入。房间按落笔顺序逐段绘制，返回已显示的首帧，网页和 PNG 会同步更新。前一组仍在绘制时，新的绘制请求返回 409。撤销、清屏或回合结束会取消剩余笔迹。 |
| `undo`、`clear` | `seq` |
| `leave` | 无 |

形状示例为 `{"kind":"rect","points":[[100,80],[750,500]],"width":6,"color":"#292d2b"}`。坐标为 1000×650 逻辑画布内的整数，`rect` 和 `ellipse` 使用外框两个对角点，`line` 使用 1–96 个顺序点。每个图形形成独立的一笔。整批校验通过才落笔。每次请求最多 4 KiB。

用 `next` 区分选词、看图、绘画、等待和结算。同房的 HTTP 和网页座位都计入 8 人上限。每次已入座的读取或行动都续期，约 45 秒无请求后走原游戏的掉线与座位回收流程。HTTP 玩家可以用原 Cookie 和 `join` 恢复仍保留的座位。读写沿用来源 IP 限流，多位玩家共用出口时可错开轮询。429 表示访问太快，503 表示待生成图片稍后再取。
