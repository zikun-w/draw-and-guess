- 开发主机：Intel Core i7-14650HX，16 核 / 24 线程。
- Linux 环境：WSL Debian 13.5，amd64。

## 400 连接回环压测

```bash
cd backend
go run ./cmd/loadtest -rooms 50 -players 8 -batches 100 -interval 40ms
```

50 个房间同时绘画，每房间 8 个连接、一名画手。每批 24 个坐标点，每 40ms 一批，共发送 100 批。

| 指标 | 参考结果 |
| --- | --- |
| 房间 / 连接 | 50 / 400 |
| 绘画阶段耗时 | 4.012 秒 |
| 预期 / 实收广播 | 40000 / 40000 |
| 业务错误 | 0 |
| P50 / P95 / P99 | 2.42 / 4.89 / 6.75 ms |
| 进程堆内存 | 36.67 MiB |
| 出站数据量 / 绘画耗时 | 6.37 MiB/s |
| 进程 CPU 时间 | 3.35 秒 |
| 清理后 goroutine 数 | 1 |

压测客户端和服务端位于同一进程，延迟是发送批次到收到广播的回环时间，内存也包含客户端与生成器开销。该场景绕过 HTTP 入场限流，未包含数据库、反向代理、TLS、公网和浏览器渲染。

因此，不能用此堆内存直接计算“每个在线用户需要多少内存”，或外推目标 VPS 的容量。部署前应在自己的服务器上分别测量后台进程 RSS、房间和绘画量、长时间运行表现，以及公网带宽与延迟。
